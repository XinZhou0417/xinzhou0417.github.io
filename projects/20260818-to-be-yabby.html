To Be Yabby, an ordering platform with two AI agents

## Background

After finishing my studies at Unimelb in May 2026, I was invited by one of my friends into a project, writing web apps for a Chinese restaurant, To Be Yabby, in Melbourne's eastern suburbs.

The original idea was simple: write an ordering system for customers and, more importantly, a management dashboard for the staff and the owner. And the team was just me and my friend, a two-person team of freshly graduated software engineers, at an extremely fast development pace. I am the AI engineer on the team. The agent stack below is mine end to end; the rest of the platform we built together.

## Building a Multi-agent AI system

The need for utilising the power of AI emerged during the development process. We primarily built two paths, based on the features of our system:

### A customer-facing phone agent, for automated order taking and basic customer service

Before the system came into being, the orders were taken manually via chat apps, then manually documented in the order book. The system provides a digital way of performing the same logic. But this phone agent changes the shape of that: everything is automatically wired — customer places an order, details recorded by the agent, new order created in the system, no human intervention needed.

### A staff-facing multi-modal agent, for basic job delegation

Unlike the customer telephony agent, the staff agent is web-based, which enables the multi-modal ability. One use case for it is the new order initiated by staff (not by the customer). This use case exists since a substantial number of the customers are still giving orders on chat apps with text messages. So, once a new order comes from the customer, the staff can directly give the screenshots to the agent. The order info will then be parsed, and will be used in next operations.

One interesting thing about this agent is that it also has the capability of manipulating the web UI. For example, in the example use case above, if the agent can parse enough information to create a new order, it will directly invoke the backend tools and create the order by itself. But, if some important info is missing (e.g. payment method), it won't invoke the tool. Instead, it will automatically open the order creation popup and fill the info in the blanks, leaving the missing info to the staff to enter. The UI manipulation is done by a subagent.

Both agents are built with Pipecat, with different transports and separate sets of permitted tools. They share some infrastructure for pipeline construction.
